# Ориентация новой серии в одном окне — 20 октября 2026

Пользователь сообщил о coronal вместо ожидаемого axial после перетаскивания
другой серии в одно окно и подтвердил предшествующее переключение через Tab.
Не помнит, выбирал ли Common 1×1 явно или разворачивал MPR двойным щелчком.
После диагностики подтвердил: явный выбор 1×1 возвращает axial для новых серий.

На искусственных axial DICOM воспроизведено сохранение coronal в развёрнутом
MPR после Tab. В настоящем Common 1×1 проблема не воспроизводится. Связь
именно с прежним состоянием пользовательского окна отдельно не зафиксирована,
но предложенный переход в Common подтверждён пользователем.

## Подтверждённый механизм

Развёрнутое MPR визуально занимает одно окно, но сохраняет
`isHangingProtocolLayout: true`, группу `mpr` и ID плоскости `mpr-coronal`.
Обработчик drop передаёт этот флаг в
`hangingProtocolService.getViewportsRequireUpdate`. При активном MPR метод
подставляет новой серии параметры окна из протокола, включая
`viewportType: volume` и `orientation: coronal`. Это также происходит для
sagittal после следующего Tab. Поведение связано с режимом окна, а не с
ориентацией исходных файлов или случайным восстановлением камеры.

Явный выбор Change layout → Common 1×1 устанавливает
`isHangingProtocolLayout: false` и группу `default`, сохраняя текущую плоскость
текущей серии. Следующий drop возвращает только ID окна и новой серии,
без MPR options. Новая серия открывается как `stack` в `acquisition`:
для искусственных axial DICOM камера имеет нормаль `[0, 0, -1]`.
Это сохраняется и после Tab в Common, включая Common после MPR, когда
`protocolId` ещё равен `mpr`. Один `protocolId` не определяет режим окна.
Исходная плоскость не обязана быть axial для произвольного DICOM.

Реализация: `www/app.bundle.872442cf365ecf1c.js`, методы `onDropHandler`,
`_getUpdatedViewports`, `getViewportsRequireUpdate`; настройка Tab —
`app-config.js`; нормализация Common — `viewer_ui.py`.

## Воспроизведение и проверка

До оформления итогового теста запуск с ожиданием axial после drop в
развёрнутый coronal MPR завершился AssertionError: фактическая нормаль
`[0, -1, 0]`, ориентация `coronal`, тип `orthographic`. Смена только режима
через Common 1×1 убирает этот эффект, не меняя серию до следующего drop.

Постоянный тест проверяет семь сценариев, реальный drag-and-drop мышью,
Tab, меню Common, метаданные окна и фактическую нормаль камеры. Он явно
фиксирует текущее поведение MPR и ожидаемый axial в Common; конфигурацию
и сборку приложения не изменяет. Используются только искусственные данные
и отдельный Chromium. Ошибок JavaScript и внешних запросов нет.

```bash
.venv/bin/python verification/make-import-fixtures.py /tmp/ohif-import-fixtures
OHIF_PLAYWRIGHT_PATH=/path/to/playwright node verification/test-common-drop-orientation.cjs /tmp/ohif-import-fixtures/two-series
```

Результат: `verification/common-drop-orientation.json`, `PASS`, семь проверок.
Рабочие настройки и bundles не изменялись. Для ожидаемого поведения нужно
явно выбрать Common 1×1 перед переносом новой серии. Если после такого выбора
сбой сохранится, для продолжения диагностики нужен точный сценарий; текущий
тест не подтверждает дефект именно в Common.
