# OHIF — локальный просмотр DICOM

Для продолжения настройки в новой сессии: [HANDOFF.md](HANDOFF.md).
Там сохранены подтверждённые изменения, статус работы и команды проверок.

Установлена готовая веб-сборка OHIF **3.13.12** из официального образа
`ohif/app`, без запуска Docker. При скачивании проверены SHA-256 манифеста
и каждого слоя. Версия и точный digest записаны в `installed-version.json`.

## Nix / flakes

В репозитории два вида содержимого, и они живут по разным правилам:

| Часть | Где хранится | Как появляется |
|---|---|---|
| Код: `server.py`, `local_metadata.py`, `viewer_ui.py`, патчи `compatibility/`, проверки `verification/`, документация | git | редактируется напрямую |
| `www/` — готовые бандлы вьюера (226 МБ), `.venv/`, `backups/` | локально, в `.gitignore` | `python3 install-viewer.py`, `python3 -m venv .venv`, сессионные архивы |

Flake описывает только код, поэтому `www/` передаётся серверу во время запуска
через переменную `OHIF_SITE` (по умолчанию `~/Work/ohif/www`).

```bash
nix build .                       # пакет ohif-local → ./result
nix run .                         # то же, сразу запуск сервера
OHIF_SITE=/путь/к/www nix run .    # другой каталог со сборкой вьюера
nix develop                       # python3 + pydicom 3.0.2, node, curl, unzip
nix flake update                  # обновить nixpkgs; изменения — в git diff flake.lock
nix flake check
```

В NixOS эта сборка подключается как input флейка конфигурации:

```nix
inputs.ohif.url = "github:shulgarv/ohif";
```

и используется через `inputs.ohif.packages.x86_64-linux.default` (сервис и
unit-файл — в конфигурации NixOS, см. заметку в личном хранилище).

## Память при открытии больших исследований — 19 октября 2026

При падении на исследовании 6984280 журнал ядра зафиксировал превышение
процессом Chromium лимита 8 GiB. Все 788 DICOM прошли проверку чтения пикселей.
В импортёре устранена лишняя копия PixelData в хранилище метаданных: изображения
по-прежнему читает Cornerstone из исходных файлов. На сопоставимой искусственной
серии это освободило около 1.64 GB. Под лимитом 8 GiB проверены импорт,
отрисовка всех трёх серий и переходы к последним срезам. Системные лимиты
не менялись; исходное падение в свежем тестовом браузере не воспроизвелось,
поэтому требуется повторное открытие пользователем. Подробности — в HANDOFF.md.

## Ошибка no pixel data in NATURALIZED — 19 октября 2026

Исправлен сбой чтения исследования 6980352: некоторые числовые поля записаны
как `UN` с длиной, несовместимой с типом из словаря DICOM. Асинхронный парсер
переходил границу поля и терял последующие теги, включая PixelData. Теперь оба
читателя сохраняют такие значения как исходные байты `UN`, не подставляя числа.
Пиксели и исходные файлы не меняются.

Все 1400 DICOM архива проверены локальным парсером и поставщиком кадров;
пиксельные байты совпадают, SHA-256 архива сохранён. Отрисовка проверена в
Chromium на искусственных файлах с тем же дефектом. Исправление находится в
`compatibility/un-numeric-length.js`, применяется `apply-local-compatibility.py`.
Проверки и команды повторения — в HANDOFF.md. Для применения обновите страницу
OHIF (`Ctrl+Shift+R`) и заново выберите исследование.

axial → coronal → sagittal → axial. Работает в одном окне, выбранной ячейке

нужна реконструируемая серия. В полях ввода Tab сохраняет обычную навигацию.
Прежний цикл проекций в развёрнутом MPR сохранён.

Проверка: `verification/test-common-tab.cjs`, результат — `verification/common-tab.json`.
Она использует те же искусственные серии `two-series`:

```bash

```

окнах и MPR. **F2** открывает MPR текущей серии, **F3** включает/выключает

Проверка использует две искусственные серии, реальное рисование Freehand ROI

## Как открыть исследование

1. В меню приложений (`Super + Space`) найдите **OHIF**.
2. Нажмите **Load folders** и выберите папку исследования в
   `/home/srv/Downloads`. Вложенные папки также будут прочитаны.
3. Для отдельных файлов используйте **Load files / ZIP**. Можно также перетащить
   DICOM-файлы, ZIP-архив или папку в окно OHIF.

Если исследование пришло в ZIP-архиве, нажмите **Load files / ZIP** и выберите
архив либо перетащите его в окно OHIF. Папки внутри архива раскрываются
автоматически, DICOMDIR исключается из списка исследований. Обычные сопутствующие
текстовые файлы, PDF и программы просмотра пропускаются. Распаковка выполняется
в браузере без создания папок на диске. Можно выбрать несколько архивов или
архивы вместе с отдельными DICOM-файлами. При загрузке отображается индикатор.

Поддерживаются ZIP без сжатия, DEFLATE и ZIP64. Встроенные ZIP внутри ZIP
не раскрываются; архивы с паролем нужно распаковать вручную. Контроль CRC
проверяет целостность извлечённых файлов. Если файл повреждён, появляется
предупреждение о неполном исследовании. Для ограничения расхода памяти
размер одного распакованного файла ограничен 512 MiB, сумма файлов — 8 GiB,
количество — 100000; превышение сопровождается сообщением.

Служебный файл экспорта `info.famed` пропускается при открытии папок, отдельных
файлов и ZIP, без предупреждения о неполном исследовании. Регистр имени не важен.
Повреждённые DICOM и неизвестные файлы по-прежнему вызывают предупреждение.

Используется локальная копия `@zip.js/zip.js` **2.23.0** с лицензией BSD-3-Clause.
При установке библиотеки проверен SHA-512 npm-пакета. Исходники, лицензия
и запись версии находятся в `compatibility/vendor/`. Внешние запросы для ZIP
не нужны. API библиотеки: <https://gildas-lormeau.github.io/zip.js/api/classes/ZipReader.html>.

### Быстрая распаковка архивов

Нажмите **Super + Alt + Z** (Super — клавиша Windows).
`unpack-downloads.py` распакует все новые `.zip`/`.ZIP` непосредственно
из Downloads: `study.zip` → `Downloads/study/`. Даже файлы из корня
ZIP останутся внутри этой отдельной папки. Вложенная структура сохраняется.
ZIP-архивы не удаляются. ZIP внутри других папок или архивов не обрабатываются.

Уже успешно обработанные неизменённые архивы пропускаются, если папка
результата ещё существует. Если архив изменился или папка была удалена,
он будет распакован снова. При совпадении имени создаётся `study (2)/`,
`study (3)/` и так далее; существующие файлы не перезаписываются.
Журнал успешной распаковки находится в `zip-unpack-state.json` рядом
со скриптом; внутрь папок исследований служебные файлы не добавляются.

Распаковка выполняется в фоне, о начале и результате сообщает уведомление.
Повторное нажатие во время работы не запускает второй процесс распаковки.
При повреждённом, зашифрованном или неподдерживаемом ZIP появится сообщение
об ошибке; другие архивы продолжают обрабатываться. Незавершённая папка
убирается при обработанной ошибке. Дождитесь завершения скачивания ZIP.

Ручной запуск:

```bash
python3 /home/srv/Work/ohif/unpack-downloads.py
```

Привязка добавлена в `~/.config/hypr/bindings.lua`, исходная версия этого
файла сохранена рядом с суффиксом `.bak.zip-unpack-…`.
Поведение проверено семью тестами на искусственных архивах во временных
папках: обычная распаковка, повторы, коллизии имён, удаление результата,
опасные пути, повреждённые ZIP, ссылки и одновременный запуск.

Адрес: <http://127.0.0.1:3000/localbasic>.
Для открытия другого исследования запустите OHIF из меню снова.

Файлы читаются в браузере: исходные DICOM не изменяются и не копируются в
серверную базу. Если браузерный парсер не поддерживает кодировку метаданных,
выбранный файл автоматически передаётся локальному обработчику pydicom
по адресу `127.0.0.1:3000/api/local-dicom-metadata`. Обработчик возвращает
декодированные метаданные, ничего не записывает на диск и не декодирует
пиксели. Изображение отображается из исходного файла. В этой установке
настроен только локальный источник данных, а политика браузера блокирует
подключения к внешним серверам.
Интернет после установки не нужен. После обновления страницы или закрытия
окна файлы нужно выбрать снова; постоянного каталога исследований нет.
При `Ctrl+R` открытого локального исследования приложение возвращается
на экран выбора папки, поскольку выбранные файлы больше не находятся в памяти
браузера. Скопированный адрес локального исследования или восстановленная
вкладка также возвращают на экран выбора; исходные DICOM нужно выбрать заново.
Downloads автоматически не сканируется — выбирайте нужную папку вручную.

## Совместимость локального импорта

Локальный загрузчик исправлен для OHIF **3.13.12**:

- DICOMDIR распознаётся как каталог и не добавляется в список исследований.
  Поэтому наличие DICOMDIR рядом с изображениями больше не создаёт исследование
  с идентификатором `undefined` и пустой просмотрщик.
- При ошибке поддержки кодировки dcmjs метаданные автоматически читает pydicom,
  включая несколько ISO 2022 кодировок, кириллицу и вложенные последовательности.
  Создавать отдельную папку «(OHIF)» для этой проблемы больше не требуется.
- Последовательности с типом `UN` читаются с Implicit VR Little Endian внутри,
  согласно DICOM PS3.5 §6.2.2 (CP-246). Исправлены первичный импортёр и
  асинхронный парсер метаданных: сохраняются все элементы последовательности,
  после неё восстанавливается формат внешних полей, в том числе при ошибке.
  Это устраняет обнаруженный `RangeError: Array buffer allocation failed`:
  асинхронный парсер принимал текст вложенного поля за длину почти 1,85 GiB.
- Импорт выполняется восемью параллельными задачами. Локальный обработчик
  метаданных обслуживает до четырёх файлов одновременно; размер одного запроса
  ограничен 512 MiB.
- Непрочитанные файлы не скрываются: появляется предупреждение с количеством.
  Если исследований нет, приложение остаётся на экране выбора файлов.

Исправления хранятся в `compatibility/*.js`, применяются скриптом
`apply-local-compatibility.py` с проверкой SHA-256 исходной сборки и автоматически
применяются при повторной установке этой закреплённой версии. Это локальная
адаптация готовой сборки, а не обновление OHIF. Исходный JavaScript сохранён
в `compatibility/app.bundle.original.js.gz`. Для другой версии потребуется

## Прежний способ ручной подготовки совместимой копии

В обнаруженном случае причина — несколько кодировок в DICOM
(`ISO 2022 IR 100` и `ISO 2022 IR 144`): локальный загрузчик этой версии
OHIF/dcmjs отклоняет такие файлы с ошибкой
`Using multiple character sets is not supported`. При отсутствии прочитанных
исследований OHIF переходит в пустой просмотрщик. Открытие другого браузерного
адреса не устраняет несовместимость.

Для этого случая ранее использовался `prepare-for-ohif.py`. Сейчас это
необязательный отдельный инструмент. Он создаёт рядом с исходной
папкой отдельную копию с суффиксом **`(OHIF)`**. Текстовые поля, включая
вложенные последовательности, переводятся в UTF-8 (`ISO_IR 192`).
После записи каждого файла проверяются все остальные значения метаданных,
байты PixelData и SHA-256 исходного файла. Исходники сохраняются.
Служебный DICOMDIR в копию не включается: OHIF открывает изображения напрямую,
а переписывать каталог с файловыми смещениями не требуется.

```bash
/home/srv/Work/ohif/.venv/bin/python /home/srv/Work/ohif/prepare-for-ohif.py "/home/srv/Downloads/папка исследования"
```

При использовании этого ручного инструмента выбирайте полученную папку
**`(OHIF)`**. При обычной работе открывайте исходную папку — обработчик кодировок
срабатывает автоматически. Хоткей распаковки ZIP
выполняет обычную распаковку. Зависимость `pydicom==3.0.2` установлена
только в локальное окружение `.venv` этой установки.
Преобразование кириллицы и вложенных полей проверено на искусственном DICOM;
для реального исследования проверены 732 изображения и 733 исходных файла.

Документация обработки кодировок:
<https://pydicom.github.io/pydicom/stable/reference/generated/pydicom.charset.decode_element.html>.
